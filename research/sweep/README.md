# Plugin entry-point sweep

Concrete unauthenticated entry points extracted from the plugin corpora in
`/home/user/sources/code` (207 TYPO3 extensions, 194 PrestaShop modules, Liferay
in-tree modules). Generated by `sweep_entrypoints.sh`. Heuristic (grep-based) —
a research map to prioritise, not proof of reachability.

## PrestaShop — `?fc=module&module=<module>&controller=<controller_param>`
- **195 / 207** front controllers are pre-auth (`auth_required != true`; PS
  `ModuleFrontController::$auth` defaults to false).
- `auth_required=true` marks the handful that *do* require a customer session.
- `ajax=yes` flags controllers exposing `ajaxProcess*` / `displayAjax` — 9 found,
  but this undercounts (many modules handle input in `initContent`/`postProcess`);
  treat the full pre-auth list as the surface. High-signal examples:
  `proxy`, `pow-captcha-for-prestashop/ajax`, `resurs-checkout-*/savedelivery`.
- Sweep every `code/prestashop-modules/*/controllers/front/*.php` for direct
  `Db::getInstance()` on `Tools::getValue(...)`, file ops, `Tools::redirect`.

## TYPO3
- **eID handlers (run before FE auth — the prime pre-auth surface)** found in
  installed extensions:
  `cundd_rest → rest` (whole REST API), `apache-solr-for-typo3/solr → tx_solr_api`,
  `in2code/powermail → powermailEidGetLocation`,
  `beechit/fal-securedownload → FalSecuredownloadFileTreeState` (access-control
  relevant), `reelworx/rx-shariff → shariff`, `t3monitor/... → t3monitoring`.
  Reach via `index.php?eID=<identifier>`.
- **89 request middlewares** registered by extensions (run in the FE/BE request
  chain pre-auth) — inspect each for auth assumptions.
- **fe_plugin** rows: extbase controller::action reachable via a FE plugin
  (`?tx_<ext>_<plugin>[action]=...`) without a login.

## Liferay — portlet `javax.portlet.action` / resource commands
- 1092 `mvc.command.name` handlers (**1078 action**, **14 resource**) across
  in-tree modules; cross-reference with a component's `guest`/auth properties and
  the `auth.public.paths` list (see `../PREAUTH_SURFACE.md`) to isolate the
  genuinely unauthenticated ones. Densest modules: `layout` (225), `commerce`
  (148), `journal` (64), `fragment`, `dynamic-data-mapping`, `document-library`.
